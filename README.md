# pe-localize

**PE 资源字符串本地化工具** —— 提取并原地翻译 Windows 可执行文件（.exe / .dll）里的界面文字（菜单、对话框、字符串表），无需重编译资源。

纯 Python 实现，零依赖（仅标准库）。

## 它做什么

Windows 程序的界面文字存放在 PE 文件的 `.rsrc` 资源段里，主要有三类：

| 资源类型 | 内容 |
|---|---|
| `RT_STRING` (6) | 字符串表（16 条一组） |
| `RT_MENU` (4) | 菜单项文字 |
| `RT_DIALOG` (5) | 对话框标题、控件文字 |

本工具：

1. **extract**：解析资源树，定位每条文字在文件中的**绝对字节偏移**，导出成 `{原文: 原文}` 的 JSON 映射（供你填入译文）。
2. **patch**：把 `{原文: 译文}` 映射**原地等长替换**回二进制——译文比原文短则用空格填充，比原文长则安全跳过。**绝不重编译资源、绝不改变文件大小**，因此不会破坏资源树结构，程序可正常启动。

### 为什么"等长替换"是关键

直接修改文字字节而不改变长度，意味着资源树里所有的 RVA/大小/偏移都保持不变。相比之下，用资源编辑器"重编译对话框"往往会改变资源布局，容易引入隐蔽错误（程序报"不受支持的操作"、点某菜单闪退等）。等长替换从原理上规避了这类问题。

## 用法

```bash
# 1. 提取待翻译文字
python pe_localize.py extract app.exe -o strings.json

# 2. 编辑 strings.json，把值改成译文
#    {"File": "文件", "Edit": "编辑", ...}
#    （可删掉不想翻的条目；保持 key 不变）

# 3. 写回（生成新文件，不改动原文件）
python pe_localize.py patch app.exe strings.json -o app_localized.exe
```

patch 时：
- 译文**长度 ≤ 原文**才会写入，超长的自动跳过并在末尾报告（安全，不会写坏）。
- 输出是**新文件**，原文件保持不变。请自行备份、自行对比测试。

> 💡 **给不熟悉命令行的朋友**：整个流程其实就是「提取 → 填翻译 → 写回」三步。如果你平时不常接触这类操作，完全可以把本工具和这份 README 一起交给 AI 助手，请它帮你把这几步跑完——现在的 AI 对这类任务通常理解得不错，你只要准备好自己有权本地化的那份软件、以及想翻译的文字即可。

## 翻译建议

- **保留格式符**：`%d`、`%s`、`%1`、`\t`、`\n` 等必须原样保留，否则程序会崩溃或显示错乱。
- **保留助记符**：菜单/按钮的 `&F` 这类快捷键标记，建议译成 `文件(&F)` 形式。
- **不译专有名词**：产品名、类名、标识符、字体名、通配符等保持原样。
- **术语统一**：同一概念全文一致（如 Debug=调试、Build=编译、Breakpoint=断点）。
- **长度**：等长替换要求译文不超原文。中文通常比英文短，一般够用；不够时可适当精简。
